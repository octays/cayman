# davlgd/p2sync 对 Cayman 的参考价值

评估日期：2026-10-14。目标仓库：[davlgd/p2sync](https://github.com/davlgd/p2sync)。

## 1. 结论与证据范围

建议把它作为同步引擎的参考项目，暂不将整个项目作为 Cayman 的基础，也不直接添加 Git 依赖。Cayman 保留 croc 中继接入和短暗号首次配对；目录比对、块复用和冲突处理保持独立于网络层。

本次成功读取仓库主页和内嵌 README。源码文件、Cargo.toml 和 CHANGELOG 的网页抓取未成功；本地 git clone 因 GitHub DNS 解析失败未完成。因此本次没有固定 commit、逐函数审查、编译、测试或性能实测。下面明确区分项目文档声明与 Cayman 的设计判断。

## 2. README 声明的能力

项目文档描述：

- Rust workspace 分为核心、网络和 CLI 三层。
- 同步采用 BLAKE3、Merkle 树比对、可配置分块，使用 watcher 和向量时钟检测变化及冲突。
- 网络采用 libp2p，连接使用 TCP + Noise + Yamux；支持 mDNS、DHT 和可选 relay。
- CLI 提供 share、持续 sync、一次性 fetch 及 relay；配对入口使用 PeerId。
- 仓库标注 Apache-2.0。

这些是项目自述，尚未验证实际执行路径、默认授权行为和测试覆盖。[来源：项目 README](https://github.com/davlgd/p2sync#readme)

不能仅从“可配置块大小”推断它实现了 CDC，也不能从 Noise 加密推断它已完成目录访问授权或短暗号 PAKE。

## 3. 与 Cayman 的适配判断

| 方面 | Cayman 决策 | 原因与后续验证 |
| --- | --- | --- |
| 核心与网络分离 | 借鉴 | 便于 croc 中继和未来直连共用同步引擎 |
| Merkle 索引 | 保留规模优化路线 | 需检查叶子是否绑定路径、类型、版本和删除状态 |
| 块清单与按需请求 | 借鉴 | 需验证是否按块复用，还是某些路径退回整文件 |
| BLAKE3 | 加入基准候选 | 与 SHA-256 实测 CPU/吞吐后再决定，协议必须标明算法 |
| 向量时钟 | 用于双向阶段 | 需验证持久化、重启、删除冲突及历史回收 |
| watcher | 借鉴事件合并方式 | Cayman 仍要求周期扫描、溢出修复和内容核验 |
| libp2p 网络 | 首版不引入 | 不能将 libp2p relay 直接连接到 Go croc relay |
| PeerId / Noise | 不替代现有配对设计 | 身份标识和加密连接仍需绑定用户确认的目录授权 |
| core crate 代码复用 | 待源码审查 | 需要确认公共 API、网络依赖、许可证文件和维护约束 |

这里“不直接兼容 croc”是基于两个方案的协议分层作出的工程判断，不是对该项目网络功能的缺陷判定。若未来选择整体复用其 libp2p 栈，应作为明确的架构变更，同时重新评估中继部署和互操作目标。

## 4. 值得加入 Cayman 的具体改进

1. **固定分块基准增加 256 KiB 档位。** 与目前 1 MiB 比较小改动流量、清单大小、随机 I/O 和 CPU，不立即更改默认值。
2. **核心模块显式隔离传输。** `scan/index/chunk/diff/reconcile` 不依赖具体 socket；网络层承载有界消息，存储层负责持久化与原子提交。
3. **忽略规则采用内容确认。** 接收端自身写入产生的事件，通过已提交版本与实际内容匹配消除回声，不能仅在固定时间窗口内丢弃所有事件，否则可能漏掉用户编辑。
4. **删除记录回收依赖确认进度。** 时间保留期只控制容量，不能单靠到期删除 tombstone；离线对端回来必须完整对账，避免旧文件复活。
5. **增加同步观测指标。** 展示块复用率、清单字节、待办路径、冲突、扫描积压和恢复次数；吞吐高不等于同步正确。

以上为 Cayman 的设计要求，不是已经确认的 p2sync 缺陷。

## 5. 直接复用前的源码检查清单

- 固定 commit，读取 workspace 依赖、实际 LICENSE/NOTICE、CI 和测试；主页许可证标记不替代源文件核对。
- 追踪一次文件修改从 watcher 到索引、块请求、写盘、ACK 的完整路径，确认不会发送旧内容版本或漏掉后续修改。
- 检查块读取是否流式、有界，反序列化是否限长，并发请求是否共享内存预算。
- 检查对端身份的授权入口：知道 PeerId 是否足够获取目录内容；目录读写权限由谁批准，如何撤销。
- 检查临时文件、完整摘要、fsync、rename 与索引事务的崩溃恢复，最终 ACK 是否代表持久化成功。
- 检查路径穿越、符号链接、大小写冲突和文件类型变化；对端控制的路径不能逃逸本地授权根。
- 检查向量时钟和 tombstone 是否跨重启保留；丢事件、离线超期、ACK 丢失和本地并发写入是否有回归测试。
- 用真实 Go croc relay 的 Cayman 适配器验证抽离核心的工作量，不能只看模块名称判断可插拔性。

只有在这些检查与测试通过后，才决定抽取少量算法代码、维护内部 fork，还是仅参考其结构。当前不对项目成熟度或安全性作结论。
